# بنية مشروع ANTER

**آخر تحديث:** 2026-09-27

هذا المستند يوضح الملفات والمجلدات الأساسية لتشغيل وتطوير منصة ANTER، ويمنع خلطها بملفات التجارب أو بيانات البيئة المحلية.

| المسار | الغرض |
|---|---|
| `app/` | تطبيق Flask: النماذج، المسارات، الخدمات، القوالب، والملفات الثابتة. |
| `tests/` | اختبارات الوحدة والتكامل التي يجب تشغيلها قبل كل رفع. |
| `docs/` | وثائق التشغيل والتشخيص والتصميم. |
| `docs/reference/` | المرجع التقني المولَّد تلقائيًا (routes, models, services, templates, identity, integrations). |
| `docs/legacy/` | وثائق تاريخية (تشخيص حوادث، فحوصات قديمة). |
| `scripts/` | أدوات صيانة أو تحقق يدوية لا تدخل في تشغيل الخادم. |
| `scripts/generate_reference.py` | يولّد وثائق reference/ من الكود مباشرة. |
| `scripts/verification/` | سكربتات فحص يدوي. |
| `scripts/maintenance/` | سكربتات صيانة إدارية. |
| `run.py` | نقطة تشغيل الخادم المحلي. |
| `run_termux.sh` | اختصار تشغيل مناسب لبيئة Termux. |
| `Procfile` | نقطة تشغيل النشر على Render أو خدمات مماثلة. |
| `requirements.txt` | قائمة الاعتماديات الفعلية فقط. |
| `.env` | أسرار التشغيل المحلية؛ لا يُرفع إلى GitHub. |
| `instance/` و`venv/` و`logs/` | بيانات وبيئة وسجلات محلية؛ لا تدخل في المستودع. |

## قواعد الترتيب

يجب وضع أدوات الفحص اليدوية في `scripts/verification/`، وأدوات الصيانة الإدارية في `scripts/maintenance/`، والوثائق القديمة في `docs/legacy/`. لا تُحفظ مفاتيح VAPID أو مفاتيح خدمات أخرى داخل ملفات نصية في جذر المشروع؛ تُقرأ من متغيرات البيئة فقط.

> ملاحظة أمنية: إذا سبق رفع مفتاح خاص إلى المستودع، يجب تدويره في مزود الإشعارات أو مفاتيح VAPID، لأن إزالته من النسخة الحالية لا تمحوه من تاريخ Git السابق.
